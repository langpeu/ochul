# Product Requirements

## 목표

방과후/학원 수업 현장에서 패드 하나로 학생 출결, 학부모 알림, 수업료 납부 확인을 처리한다.

## MVP 범위

### 회원가입/로그인

- 선생님은 Supabase Auth로 회원가입하고 로그인한다.
- 로그인 방식은 이메일, Apple, Google을 지원한다.
- 첫 로그인 후 선생님은 공부방을 생성한다.
- 선생님은 자신이 생성한 공부방의 수업, 학생, 출결, 납부, 알림 이력만 관리한다.
- 다른 선생님은 해당 공부방과 학생 정보를 절대 조회할 수 없어야 한다.
- 추후 공동 관리 기능을 추가하더라도 명시적으로 초대/승인된 선생님에게만 제한적으로 권한을 부여한다.

### 관리자

- 관리자 계정은 `admin` role을 가진다.
- 관리자는 선생님 목록을 볼 수 있다.
- 관리자는 선생님을 선택해 해당 선생님의 공부방 목록을 볼 수 있다.
- 관리자는 선택한 공부방에 등록된 학생 목록을 볼 수 있다.
- MVP에서 관리자는 운영 점검을 위한 조회 권한을 우선 제공하고, 수정 권한은 별도 정책으로 분리한다.

### 공부방

- 공부방은 선생님이 관리하는 운영 공간이다.
- 한 선생님은 여러 공부방을 만들 수 있다.
- 공부방에는 학생, 수업, 보호자, 납부 정보, 카카오 발송 이력이 속한다.
- MVP에서는 공부방을 만든 선생님만 해당 공부방 데이터를 볼 수 있다.
- 모든 공부방 데이터는 Supabase RLS로 선생님별 격리한다.
- 추후 여러 선생님이 같은 공부방을 함께 관리할 수 있도록 권한 구조는 준비하되, 기본값은 비공개다.

### 출석체크

- 선생님은 오늘 진행할 수업을 선택한다.
- 수업 화면에는 등록 학생 목록과 각 학생의 출석 상태가 보인다.
- 학생은 자기 이름을 선택하고 비밀번호를 입력한다.
- 출결 비밀번호는 학생이 직접 입력하는 숫자 6자리다.
- 학생이 비밀번호를 잊은 경우 선생님이 리셋하고 학생이 새 6자리 비밀번호를 다시 입력하게 한다.
- 비밀번호가 맞으면 출석으로 기록된다.
- 이미 출석 처리된 학생은 중복 출석되지 않는다.
- 선생님은 출석, 지각, 결석, 조퇴, 인정결석 상태를 수동으로 수정할 수 있다.
- 좌석 배치형 수업에서는 학생이 자기 아바타를 빈 의자로 드래그앤드롭한 뒤 비밀번호를 입력하면 출석 처리된다.
- 출석 완료 후 해당 의자에는 학생 아바타, 이름, 출석 상태가 표시된다.
- 드래그앤드롭만으로 출석을 확정하지 않고 학생 비밀번호 검증을 반드시 거친다.

### 수업방

- 수업명
- 수업 설명
- 수업 기간: 시작일, 종료일
- 요일 선택: 월~일 중 복수 선택 가능
- 수업 시간: 시작 시간, 종료 시간
- 담당 선생님
- 등록 학생 목록
- 활성/비활성 상태
- 3개월 과정, 1개월 과정, 단기 특강처럼 기간이 다른 수업을 지원한다.
- 개인 사정, 공휴일, 선생님 사정으로 휴강 또는 보강 일정을 등록할 수 있다.
- 수업 유형은 기본 수업, 보강 수업, 추가 수업으로 구분한다.
- 보강 수업은 기존 기본 수업의 특정 휴강 또는 결석 회차와 연결할 수 있다.
- 수업 생성/수정 시 교실 책상과 의자 배치를 설정할 수 있다.
- 책상/의자는 캔버스에서 드래그해 배치하고, 좌석 수와 위치를 저장한다.
- 좌석은 고정 배정 또는 자유 착석 방식으로 사용할 수 있다.

### 교실 좌석 배치

- 선생님은 수업별로 책상과 의자 배치도를 만들 수 있다.
- 배치도는 패드 화면에서 한눈에 보이는 2D 교실 캔버스 형태다.
- 책상과 의자는 자유 배치, 행/열 자동 배치, 삭제, 이동을 지원한다.
- 좌석에는 학생을 미리 배정할 수 있고, 미배정 자유 좌석으로 둘 수도 있다.
- 보강 수업은 기본 수업의 좌석 배치를 복사하거나 별도 배치를 가질 수 있다.
- 배치 변경은 사용 히스토리에 기록한다.

### 수업 일정 변경

- 정규 수업 일정에서 특정 회차를 휴강 처리할 수 있다.
- 휴강된 회차의 보강 수업을 별도 날짜/시간으로 등록할 수 있다.
- 수업 시간, 장소, 휴강, 보강 변경이 생기면 보호자에게 카카오 알림을 발송한다.
- 변경 알림에는 학생 이름, 수업 이름, 기존 일정, 변경 일정, 변경 사유를 포함한다.
- 변경 이력은 선생님 보드에서 수업별/학생별로 확인할 수 있어야 한다.

### 학생

- 학생명
- 학생번호 또는 내부 코드
- 출석 비밀번호: 숫자 6자리
- 보호자 연락처
- 아바타 성별: 남, 여, 미지정
- 아바타 연령대: 초등, 중등, 고등
- 아바타 이미지 키
- 등록 수업
- 활성/휴원/퇴원 상태
- 선생님은 학생 목록에서 학생을 드래그앤드롭으로 수업방에 등록할 수 있다.
- 학생은 여러 기본 수업에 등록될 수 있다.
- 학생은 필요에 따라 보강 수업에도 추가 등록될 수 있다.
- 같은 학생이 같은 수업에 중복 등록되지 않아야 한다.

### 보호자 연락처/동의

- 보호자 휴대폰번호는 개인정보로 취급한다.
- 선생님은 학생 등록 시 보호자 전화번호를 입력할 수 있다.
- 보호자 전화번호 입력 전 또는 입력 시 다음 목적을 고지하고 동의를 확인해야 한다.
  - 출결 알림
  - 수업 휴강/보강/시간 변경 안내
  - 수업료 납부 및 미납 안내
- 선생님은 보호자에게 알림 발송 동의를 받았음을 체크해야 보호자 연락처를 저장할 수 있다.
- 동의 일시, 동의 방식, 입력한 선생님을 기록한다.
- 보호자는 수신 거부 또는 정보 삭제를 요청할 수 있어야 한다.
- 학생 출석 모드에는 보호자 전화번호가 절대 노출되지 않는다.
- 선생님 모드와 관리자 모드에서도 필요한 화면에서만 제한적으로 표시한다.
- 카카오 발송 로그와 감사 로그에는 보호자 전화번호 원문을 저장하지 않는다.
- 발송 로그에는 `010****1234` 형태의 마스킹 번호만 저장한다.

### 학생 아바타

- 학생은 귀엽고 친근한 아바타로 표시된다.
- 아바타는 남/여/미지정과 초등/중등/고등 연령대를 구분할 수 있어야 한다.
- 아바타 스타일은 학원/공부방 서비스에 맞게 밝고 깔끔하되 지나치게 유아적이지 않게 한다.
- 기본 아바타 세트는 앱 번들 에셋으로 제공한다.
- 실제 학생 사진은 MVP 범위에서 사용하지 않는다.

### 카카오 알림

- 출석 처리 시 보호자에게 발송한다.
- 결석 또는 지각 수동 처리 시 발송할 수 있다.
- 휴강, 보강, 수업 시간 변경 시 보호자에게 발송한다.
- 수업료 납부 마감 전 미납자에게 자동 안내를 발송한다.
- 모든 발송 요청과 결과를 로그로 저장한다.
- 한 보호자에게 여러 자녀가 등록될 수 있으므로 모든 알림에는 학생 이름과 수업 이름을 포함한다.
- 출석 알림에는 학생 이름, 수업 이름, 출석 상태, 출석 시간을 포함한다.
- 알림 발송 이력은 학생별, 보호자별, 수업별로 필터링할 수 있다.

### 수업료 납부

- 학생별 월별 납부 상태를 관리한다.
- 납부 상태: 미납, 납부완료, 면제, 환불, 부분납부
- 마감일 전 자동 안내 대상자를 조회할 수 있다.

### 사용 히스토리/감사 로그

- 선생님과 관리자는 앱 사용 히스토리를 확인할 수 있다.
- 학생 등록, 수정, 삭제 이력을 남긴다.
- 수업 등록, 수정, 삭제 이력을 남긴다.
- 수업별 학생 등록/제외 이력을 남긴다.
- 출결 수동 수정 이력을 남긴다.
- 수업료 납부 상태 변경 이력을 남긴다.
- 카카오 메시지 발송 요청, 성공, 실패, 재발송 이력을 확인할 수 있다.
- 히스토리는 유형, 기간, 선생님, 공부방, 학생, 수업, 카카오 발송 상태로 필터링할 수 있다.
- 선생님은 자기 공부방의 히스토리만 볼 수 있다.
- 관리자는 선생님별/공부방별 히스토리를 조회할 수 있다.
- 각 이력은 누가, 언제, 무엇을 변경했는지 확인 가능해야 한다.
- IP, 기기 식별자, user agent 같은 불필요한 접속 정보는 저장하지 않는다.

## MVP 제외

- 안면인식
- Face ID 기반 학생 인증
- BLE 근거리 체크
- 학생폰 앱
- PG 자동 결제 확인
- 학부모용 별도 앱

4. 수업 출석 체크 화면
5. 학생 비밀번호 입력 화면
6. 출석 현황/수동 수정 화면
7. 학생 관리
8. 수업 관리
9. 교실 책상/의자 배치 편집 화면

11. 좌석 배치형 출석체크 화면
12. 납부 관리
13. 알림 발송 로그
14. 사용 히스토리/감사 로그

## 화면 모드

### 학생 출석 모드

- 패드가 책상 위에 놓인 상태에서 학생이 직접 사용하는 화면이다.
- 오늘 열려있는 수업 목록을 보여준다.
- 수업을 선택하면 학생 목록과 출석 상태가 보인다.
- 학생은 자기 이름을 선택한 뒤 비밀번호를 입력한다.
- 좌석 배치형 수업에서는 학생이 자기 아바타를 빈 의자로 끌어다 놓고 비밀번호를 입력한다.
- 민감한 보호자 연락처, 납부 상태, 전체 발송 이력은 학생 출석 모드에 노출하지 않는다.

### 선생님 모드

- 수업 목록, 출석 현황, 납부 현황, 카카오 발송 이력, 수업 일정 변경을 관리한다.
- 학생/수업/출결/납부/카카오 발송 히스토리를 필터로 확인한다.
- 공부방별로 수업과 학생을 관리한다.
- 수업별 책상/의자 배치도를 만들고 수정한다.
- 학생 목록에서 수업방으로 드래그앤드롭하여 수강 등록을 관리한다.
- 기본 수업과 보강 수업에 등록된 학생을 구분해 볼 수 있어야 한다.
- 선생님 모드 진입 시 재인증을 요구한다.
- iPad/iPhone에서는 Face ID 또는 기기 생체 인증을 사용할 수 있다.
- Android 패드에서는 기기 생체 인증, 패턴, PIN 중 사용 가능한 방식을 사용한다.
- 기기 인증이 실패하거나 지원되지 않으면 앱 관리자 PIN으로 fallback 한다.
- 앱 관리자 PIN은 해당 패드의 보안 저장소에만 저장하고 Supabase에는 저장하지 않는다.
- 선생님 모드에서는 학생별 카카오 발송 이력을 구분해서 볼 수 있어야 한다.
- 보호자 1명이 여러 학생을 가진 경우에도 학생별 알림 이력이 섞이지 않게 표시한다.

### 관리자 모드

- 관리자 계정으로 로그인한 경우 선생님 목록을 볼 수 있다.
- 선생님을 선택하면 그 선생님이 소유한 공부방 목록이 보인다.
- 공부방을 선택하면 등록 학생 목록과 기본 정보를 볼 수 있다.
- 선생님별/공부방별 사용 히스토리와 카카오 발송 이력을 조회할 수 있다.
- 관리자 조회 화면은 선생님별 데이터 격리 상태를 점검할 수 있어야 한다.

## 출석 상태

- `present`: 출석
- `late`: 지각
- `absent`: 결석
- `excused`: 인정결석
- `left_early`: 조퇴

## 보안/개인정보 원칙

- 공부방, 학생, 보호자, 수업, 출결, 납부, 알림 이력은 소유 선생님만 조회할 수 있다.
- 다른 선생님의 계정에서는 내 공부방 이름조차 목록에 나타나지 않아야 한다.
- 단, `admin` role 계정은 관리자 화면에서 선생님 목록과 선생님별 공부방/학생 목록을 조회할 수 있다.
- Flutter 앱은 Supabase DB를 직접 조회하거나 수정하지 않는다.
- 앱의 모든 데이터 읽기/쓰기는 Edge Function API를 통해서만 수행한다.
- Flutter 코드에는 테이블명, 컬럼명, SQL, PostgREST query filter가 노출되지 않아야 한다.
- Supabase anon key는 Auth와 Edge Function 호출에만 사용한다.
- 학생 출결 비밀번호는 숫자 6자리이며 해시로만 저장한다.
- 선생님은 학생 출결 비밀번호를 조회할 수 없고 리셋만 할 수 있다.
- 보호자 연락처는 권한 있는 사용자만 볼 수 있고, 수집 목적과 동의 기록을 함께 관리한다.
- 카카오 발송 로그와 감사 로그에는 보호자 전화번호 원문을 남기지 않는다.
- 출석 수정 내역은 감사 로그로 남긴다.
- 학생/수업/출결/납부/알림 관련 주요 변경은 감사 로그로 남긴다.
- 감사 로그에는 IP, 기기 식별자, user agent를 저장하지 않는다.
- 알림 발송 payload에는 필요한 최소 정보만 포함한다.
- Face ID는 학생 식별용이 아니라 선생님 모드 진입 보호용으로만 사용한다.
- 선생님 모드 fallback PIN은 기기 로컬 보호 장치이며 학생 출결 비밀번호와 분리한다.

## 법적/운영 체크리스트

이 문서는 법률 자문이 아니며, 실제 운영 전 개인정보 처리방침, 보호자 동의서, 카카오 발송 위탁 고지, 내부 운영정책은 별도 검토한다.

- 만 14세 미만 학생 개인정보를 처리하는 경우 법정대리인 동의 흐름을 준비한다.
- 수집 항목, 이용 목적, 보유 기간, 파기 방법을 개인정보 처리방침에 명확히 적는다.
- 학생 이름, 보호자 연락처, 출결, 납부 상태는 개인정보로 보고 최소 수집한다.
- 카카오 알림 발송 대행사를 쓰는 경우 개인정보 처리 위탁 내용을 개인정보 처리방침에 반영한다.
- 개인정보처리시스템 접속기록은 안전성 확보조치 기준에 맞게 보관/점검한다.
- 출결/납부/알림 히스토리는 업무 확인 목적에 필요한 범위로만 저장한다.
- CCTV/영상/안면인식은 MVP 범위에서 제외한다. 추후 도입 시 영상정보처리기기 운영방침 또는 생체정보 처리 기준을 별도로 검토한다.
